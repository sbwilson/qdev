# E5S4: Storage Configuration Consistency for Leases & Hook Resilience

Harmonize storage configuration for lease discovery across configured workspaces, and make git hook installation resilient to sandbox/permission restrictions.

## Acceptance Criteria

1. Update `find_workspace_leases` and `find_active_lease` in `crates/qdev-core/src/lease.rs` to accept `Option<&StorageConfig>` and locate leases in the configured qdev directory (via `init::qdev_dir(workspace_root, storage)` or storage configuration) rather than hardcoding `.qdev/leases`.
2. Workspaces with custom storage paths (e.g., `cache_dir = "custom/.qdev/cache"`) correctly discover and manage scope leases across CLI and core commands.
3. In `qdev install hooks` and hook installation routines, handle `EPERM` / `EACCES` permission errors gracefully when `.git/hooks` is read-only or restricted by sandbox isolation, emitting an actionable instruction instead of an unhandled panic.
4. `qdev doctor` reports hook installation status without panicking or failing abruptly in sandboxed environments.
5. All workspace tests, clippy, formatting, and hygiene checks pass cleanly.
