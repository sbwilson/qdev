#### 1. Architecture Delta & Boundary Evolution
- **Source:** [`crates/qdev-core/src/lib.rs`](file:///Users/sim/dev/qdev/crates/qdev-core/src/lib.rs), [`crates/qdev-core/tests/architecture_tests.rs`](file:///Users/sim/dev/qdev/crates/qdev-core/tests/architecture_tests.rs)
- **Observation:** Epic 2 introduced 11 new domain modules into `qdev-core`: `transition`, `lease`, `governance`, `scratch`, `decision`, `dw`, `sprint`, `chore`, `next`, `pulse`, and `modules`. Core architecture rules were maintained:
  - No terminal I/O dependencies entered `qdev-core` (verified by `test_qdev_core_sources_do_not_perform_direct_terminal_io`).
  - No forbidden CLI/network crates entered core (verified by `test_qdev_core_manifest_has_no_forbidden_dependencies`).
  - The architectural identity rule ("which file holds entity X has exactly one implementation") was strictly extended and preserved across `decision.rs`, `dw.rs`, `sprint.rs`, and `chore.rs`, passing `test_the_identity_rule_has_exactly_one_set_of_sites`.
- **Disposition:** *Accept as-is*. The architectural boundary between `qdev-core` and `qdev-cli` remains intact.

#### 2. God-Class / Size Growth
- **Source:** [`crates/qdev-cli/src/main.rs`](file:///Users/sim/dev/qdev/crates/qdev-cli/src/main.rs#L1)
- **Observation:** `crates/qdev-cli/src/main.rs` experienced massive growth, increasing by 3,409 lines across 16 commits during Epic 2, reaching 6,605 lines. Over 40 discrete `handle_*` functions reside in this single file. Handlers for `transition`, `constraint`, `scratch`, `decision`, `dw`, `sprint`, and `chore` each contribute 150–400 lines of dispatch, interactivity checking, payload shaping, and error translation.
- **Disposition:** *Fix now* (Action Item). Propose decomposing `main.rs` into focused handler modules under `crates/qdev-cli/src/handlers/` before Epic 3 adds verification gates, hooks, and MCP server surfaces.

#### 3. Duplication Map
- **Source:** [`crates/qdev-cli/src/main.rs:2648-2695`](file:///Users/sim/dev/qdev/crates/qdev-cli/src/main.rs#L2648-L2695)
- **Observation:** Author resolution logic (`resolve_author`) is called from 23 separate handler locations in `main.rs`. Furthermore, `resolve_author` resides strictly in `qdev-cli`, forcing core modules such as `pulse.rs` and `next.rs` to rely on caller-injected author information rather than standard core attribution helpers.
- **Disposition:** *Fix now* (Action Item). Promote author resolution into `qdev-core::identity` or `qdev-core::write` to eliminate CLI boilerplate and provide unified attribution across all layers.

#### 4. Pattern Divergence
- **Source:** [`crates/qdev-core/src/lease.rs:301`](file:///Users/sim/dev/qdev/crates/qdev-core/src/lease.rs#L301), [`docs/bmad/implementation-artifacts/deferred-work.md:474`](file:///Users/sim/dev/qdev/docs/bmad/implementation-artifacts/deferred-work.md#L474)
- **Observation:** While Story 2.10 adapted chore storage (`chore_dir`) to respect `StorageConfig::cache_dir`, `lease.rs` still hardcodes `.qdev/leases`. If a workspace relocates its cache directory via configuration, leases continue to be written to `.qdev/leases`, diverging from the configured storage convention.
- **Disposition:** *Defer* (tracked in `deferred-work.md:474`). Thread `StorageConfig` through `lease.rs` when storage configuration is unified in Epic 3.

#### 5. Spec-to-Implementation Reconciliation
- **Source:** [`docs/bmad/implementation-artifacts/spec-2-10-chores-with-path-allowlists.md:22`](file:///Users/sim/dev/qdev/docs/bmad/implementation-artifacts/spec-2-10-chores-with-path-allowlists.md#L22), [`docs/bmad/implementation-artifacts/deferred-work.md:461`](file:///Users/sim/dev/qdev/docs/bmad/implementation-artifacts/deferred-work.md#L461)

### Code Lenses (Diff-Scope Review)

#### Lens 1: Verification Gap / Seam Defect in State Machine Transitions
- **Location:** [`crates/qdev-core/src/transition.rs:696-735`](file:///Users/sim/dev/qdev/crates/qdev-core/src/transition.rs#L696-L735)
- **Trigger Condition:** In `TransitionEngine::transition`, Step 4 (`close_deferred_work`, lines 700–706) and Step 5 (`auto_release_lease`, lines 712–714) execute *before* Step 6 (`pre_transition` hooks, lines 728–730) and Step 7 (`apply_entity_update_checked`, lines 750–759).
- **Consequence:** If any registered `pre_transition` hook refuses (e.g. an Epic 3 verification gate fails) or optimistic concurrency check (`if_version`) rejects the update, mutations have already leaked to the disk: target `DW-` records have already been transitioned to `status: done`, and the story lease has been purged from `.qdev/leases`, leaving the un-transitioned story stranded without a lease.
- **Disposition:** *Fix now* (Action Item). Move `close_deferred_work` and `auto_release_lease` to execute after `apply_entity_update_checked` commits successfully.

#### Lens 2: In-Flight Hook Lifecycle Contracts
- **Location:** [`crates/qdev-core/src/transition.rs:623-706`](file:///Users/sim/dev/qdev/crates/qdev-core/src/transition.rs#L623-L706), [`docs/bmad/implementation-artifacts/deferred-work.md:450-457`](file:///Users/sim/dev/qdev/docs/bmad/implementation-artifacts/deferred-work.md#L450-L457)
- **Trigger Condition:** `handle_transition` in `main.rs` initializes `TransitionEngine::new()` with empty hooks. Hook registration and configuration have no CLI flags or configuration bindings yet.
- **Consequence:** Synchronous hook execution is verified in core library tests, but cannot be configured or exercised end-to-end through the CLI.
- **Disposition:** *Defer* to Epic 3 Story 3.1 & 3.6 (where transition-bound gates provide the first external hook implementations).

#### Lens 3: Process Defect Recurrence in Sprint Status
- **Location:** [`docs/bmad/implementation-artifacts/sprint-status.yaml:66-78`](file:///Users/sim/dev/qdev/docs/bmad/implementation-artifacts/sprint-status.yaml#L66-L78)
- **Trigger Condition:** All 12 stories from 2-2 to 2-13 were fully coded and verified, but remained marked `review` in `sprint-status.yaml`, with only `2-1` marked `done`.
- **Consequence:** This is an exact recurrence of Epic 1 Action Item 9 (`epic-1-retro-item-9-process-advance-sprint-status-story-keys`), where stories completed in development were left at `review`. Under retrospective completeness rules, this forces the machine verdict to `rejected`.
